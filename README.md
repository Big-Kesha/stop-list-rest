# Стоп-лист кухни

Тестовое задание: панель стоп-листа для менеджера зала. Один экран, где видно
меню смены, можно фильтровать по цеху и статусу, ставить позиции в стоп-лист
и снимать со стопа.

Бэкенд имитирован route handlers Next.js, данные — in-memory.

# запуск node 24

- npm install

- npm run dev

- [localhost:3000](http://localhost:3000)

# Стек

- Next.js 16 (App Router), React, TypeScript (strict)
- TanStack Query — серверное состояние
- Zustand — клиентское UI-состояние (панель, тосты, флаги «в полёте»)
- Tailwind CSS
- Prettier + eslint-config-prettier

# Что сделано

- Список 15 позиций из сид-файла: GET /api/menu-items с задержкой 600 мс.
- Фильтры по цеху и статусу, живут в URL (?shop=bar&status=stopped).
  переключение между фильтрами без доп подгрузки, если данные ещё свежие
- initialFilters из page.tsx — fallback на случай, пока useSearchParams не отдал
  реальные данные. Это убирает возможный кадр с дефолтными фильтрами при первой загрузке.
- Постановка в стоп: POST /api/menu-items/:id/stop с телом { reason, until }.
- Снятие со стопа: POST /api/menu-items/:id/resume, без формы.
- Оптимистичное обновление: статус меняется мгновенно, при ошибке — откат и тост.
- Сервер искусственно отвечает с задержкой 600 мс и в ~20% случаев ошибкой 503.(можно изменить ERROR_RATE в коде)
  Искусственные ошибки — чтобы клиент обрабатывал сбои, а не имитировал их у себя.
- Состояния загрузки и ошибки — на уровне тела таблицы.
- Валидация формы (базовая без доп библиотек): причина из списка, время — не дальше 24 часов и кратно 15 минутам.
- тосты - Очередь, а не один тост: toasts: ToastItem[] в zustand, компонент ToastContainer
  рендерит стопку снизу-справа. Максимум 3 тоста одновременно, старые вытесняются
  (MAX_TOASTS в ui-store.ts). Автозакрытие через 3 секунды.

# Ошибки и загрузки

- Первый GET: useQuery.isLoading → строка «Загрузка…» в теле таблицы, шапка на месте.
- Refetch: useQuery.isFetching → тонкий индикатор «обновление…», данные остаются.
- Ошибка первого GET: ErrorRow внутри <TBody> с кнопкой «Повторить».
- Ошибка refetch, когда данные уже есть: данные остаются, ошибка — тостом.
- Ошибка мутации: откат строки (onError в хуке) + тост (onError в компоненте).
- Валидация формы: локальный useState в панели, красная обводка и текст под полем.
- Ошибка в рендере: app/error.tsx, error boundary сегмента.

isLoading и isFetching намеренно разные — это убирает «скачки» таблицы при refetch.

# Границы сервер/клиент

- app/page.tsx — серверный. Читает searchParams (в Next 16 — Promise),
  парсит их через parseFilters, передаёт как initialFilters в клиентский экран.
  Даёт первый рендер без «моргания» дефолтных фильтров.

- app/providers.tsx — клиентский, всё что внутри серверное потому что рендерится через children. Один QueryClient на приложение,
  создаётся через useState(() => new QueryClient()), чтобы не пересоздавался
  на каждом рендере. ReactQueryDevtools — только для разработки.

- app/error.tsx — клиентский. Error boundary уровня сегмента: ловит
  исключения в рендере серверных и клиентских компонентов.

- Всё, что делает fetch, useQuery, useMutation или использует хуки —
  клиентское. Презентационные компоненты (StopListTable, Filters,
  StopReasonPanel, Toast) — тоже клиентские, но не знают про транспорт.

# Слои фронта

- shared/ui — примитивы без доменных типов: Button, Spinner, Badge, Select, Table, Toast.
- features/stop-list/model — данные и логика: queries.ts (ключи кэша, fetch),
  use-stop-item.ts и use-resume-item.ts (мутации с оптимистикой),
  ui-store.ts (zustand), filters.ts и use-filters.ts (URL).
- features/stop-list/ui — компоненты. StopListScreen — оркестратор (useQuery + мутации),
  остальные — презентационные, не знают про транспорт.
- server — in-memory стор и сид. Роуты в app/api — тонкие обёртки над стором.

Правило: shared/ui не импортирует доменные типы. features/_/ui не делает fetch.
features/_/model не рендерит.

# Осознанные упрощения

- Мобильная вёрстка. Только десктоп 1280 px, как в задании.
- Нет логики учета причин стопа, например при постановке в стоп с "закончилось" не обнуляется количество в бд
